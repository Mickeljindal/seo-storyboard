# Brief: how-to-launch-a-micro-saas

## Angle (opportunity / playbook, journey shape)
For the aspiring solo founder / indie hacker who wants to launch a small, focused, profitable
software product. Not a "Do I Need X" decision guide. A journey: pick a real problem -> build lean
(MVP) -> the boring production layer that actually matters -> launch before ready -> first paying
customers -> iterate. Teach-first: solve the founder's real problem completely, product appears once
at the "run it in production" step plus the closing CTA.

## Intent
Informational / aspirational playbook. Reader wants a realistic end-to-end path to shipping a small
SaaS solo. Payoff is a clear sequence and honest guardrails, not a signup.

## Information gain (one sentence)
It orders the launch as a stubborn five-stage loop (problem -> lean MVP -> production layer -> launch
-> paying users -> iterate), names the real killers (crowded consumer idea, never shipping, never
charging, ignoring the production layer), and separates dev shortcuts from what production needs in a
table, which generic "how to start a SaaS" posts skip.

## Founder opinion + anti-pattern (honesty)
- Opinion: most micro-SaaS die from idea selection and never shipping, not from infra or stack choice.
- Anti-pattern: over-building before a single user exists (auth, dashboards, billing tiers, dark mode)
  while the core is unvalidated. Also: premature scaling.
- No income promises, no earnings figures, no timelines-to-profit, no invented statistics or market
  sizes. Trends kept general-true and unquantified.
